The efficiency problem in visual grounding

Visual grounding is the function of locating a specific object or region within a video or image based on what someone described in natural language, and produces a bounding box that pinpoints specifically where that item or object may be. Unlike traditional object detection, which primarily relies on a fixed set of class labels like "Person," "Car," or "Dog," visual grounding understands free-form, open-vocabulary queries like "the person driving the black car near the left side of the road."[1] This flexibility makes grounding models far more useful for real-world applications where the objects of interest cannot be called out in advance — such as an AI agent that needs to click a specific button on a screen, or an agent that needs to locate various objects based on a description from a user or system.

Despite how useful visual grounding systems are, existing vision-language models (VLMs) still face a fundamental efficiency problem. They generate their bounding box coordinates one number at a time, requiring four sequential decoding steps to produce a single box.[2] This token-by-token generation process creates a significant latency bottleneck, particularly in dense scenes with many objects, or in real-time applications like robotics and video analysis where speed is critical.

For this project we explored LocateAnything-3B (huggingface.co/nvidia/LocateAnything-3B), a vision-language grounding model released by NVIDIA in May 2026.[3] This model was recently released and is currently one of the top trending models on Hugging Face. LocateAnything is a generalist vision-language model — it is not trained to do just one specific thing, like only identifying cats or only scanning license plates, but instead handles a massive variety of everyday objects and concepts. It is built for one core task: point it at an image or video, describe what you are looking for in natural language, and it instantly pinpoints the exact object or region with a bounding box. This model also supports a variety of capabilities in one package, including open-vocabulary object detection, app navigation by AI agents, document analysis, and can assist robots with their perception of the world around them.[3][4]

The gap LocateAnything fills is the tradeoff between decoding speed and localization quality. Rather than accepting slower, sequential decoding as the price of accurate grounding, the model introduces a new decoding mechanism — Parallel Box Decoding (PBD) — that predicts an entire bounding box simultaneously, breaking the autoregressive bottleneck while actually improving accuracy on most benchmarks.[5][6]

Four components, one pipeline

LocateAnything is built on a standard vision-language model backbone, extended with a specialized output mechanism for efficient box generation.[3]

1

Vision Encoder — MoonViT-SO-400M

The stack starts with MoonViT, a visual transformer encoder adapted from Kimi-VL, which processes the inputted image at its native resolution (up to 2.5K) rather than forcing it into a fixed low-resolution grid. This preserves fine-grained spatial detail that is critical for precise localization, especially for small or densely packed objects.

2

MLP Projector

The visual features produced by MoonViT exist in a different space than the language model's token embeddings. A multi-layer perceptron (MLP) projector bridges this gap, transforming visual tokens into a format the language decoder can process alongside text.

3

Language Decoder — Qwen2.5-3B-Instruct

The projected visual tokens are concatenated with the tokenized natural language query (up to 24K tokens) and fed into Qwen2.5-3B-Instruct, a transformer decoder that handles both language understanding and, in the standard case, next-token generation.

4

Parallel Box Decoding (PBD) Output Head

Instead of relying solely on the decoder's standard token-by-token output layer, LocateAnything adds a specialized output that allows the model to emit an entire bounding box as one atomic unit rather than a sequence of individually predicted tokens. This is the component that most distinguishes LocateAnything from prior generalist grounding VLMs.

Overall, the model totals 3 billion parameters, making it small enough to be practical for real-time and on-device applications while still matching or exceeding the localization quality of larger specialist models.[3][5]

How Parallel Box Decoding works

In standard vision-language models, bounding box coordinates (x1, y1, x2, y2) are generated one number at a time using next-token prediction (NTP) — the same mechanism used to generate ordinary text.[2] Each coordinate is quantized into a unique token, and the model must complete four sequential decoding steps to fully specify a single box. This is similar to writing a word one letter at a time: it may work, but it is slow, and it discards the geometric relationship between the four numbers, since the model treats them as an arbitrary sequence of tokens rather than as part of a single coherent shape.

LocateAnything reframes each bounding box as an atomic six-token block rather than four independently generated numbers. The Main Idea — Parallel Box Decoding[5]

Each block consists of a <box> start token, the four quantized coordinate tokens (each normalized to a range of 0–1000), and a </box> end token.[5] Instead of predicting these six tokens sequentially, the model predicts the entire block simultaneously in a single parallel decoding step — this is Parallel Box Decoding (PBD).

A different attention mechanism

Predicting six tokens at once requires the model to attend to all of them jointly, rather than only to tokens generated before it. LocateAnything addresses this with a specialized diverse attention mask that combines three attention patterns:[5]

Standard causal attention

Within the ordinary text-generation stream — left-to-right, as in normal language modeling.

Causal attention across blocks

So that later boxes can still condition on earlier ones in the sequence.

Bidirectional attention within a block

All four coordinates and the two boundary tokens see one another, preserving the box's geometric coherence.

Dual-formulation training

To ensure the model retains strong language understanding while gaining this new parallel capability, training uses Dual-Formulation Training — a dual-objective loss combining a standard token-by-token loss (NTP) and a new block-level parallel loss (MTP), optimized jointly on the same training sequence composed of visual tokens, the query, the NTP target, and the block-level target.[5]

The payoff

LocateAnything-3B (PBD)12.7 BPS
Rex-Omni5.0 BPS

Boxes per second (BPS) on an H100 GPU. PBD reaches over 10× the throughput of Qwen3-VL and 2.5× that of Rex-Omni.[5][6]

Because PBD collapses four sequential decoding steps into one parallel step, LocateAnything achieves up to 2.5× higher throughput than prior approaches. Critically, this speedup does not come at the cost of accuracy: because the bidirectional attention within each block preserves the geometric relationship between the four coordinates, PBD actually improves localization quality on most benchmarks compared to standard autoregressive decoding.[5][6]

Training

Training Strategy

The training process for LocateAnything-3B consists of four stages. While the last two steps concentrate the model for object identification, visual grounding, and dense scenes, the first two levels establish broad visual-language understanding. This method enables the model to retain a wide range of reasoning skills prior to applying significant bounding-box supervision.

Both parallel and autoregressive decoding are supported by the model through dual-formulation training. While Multi-Token Prediction (MTP) trains the language model to create bounding box coordinates in parallel, Next-Token Prediction (NTP) maintains the model's capacity to generate tokens sequentially. One model checkpoint may enable Fast, Hybrid, and Slow inference modes since both objectives are trained simultaneously.[5]

The various prediction streams are controlled by a heterogeneous attention mask. Causal attention is used in the prompt, visual context, and NTP output. Block-causal attention between bounding boxes and bidirectional attention inside each box are used in the MTP output. To avoid information leakage between their prediction goals, the NTP and MTP outputs are kept apart.[5]

Four-Stage Training Pipeline

Stage Main Objective Training Data
1 Align visual features with the language decoder Image-caption data
2 Develop broad multimodal understanding VQA, OCR, charts, science, mathematics, code, counting, and instruction data
3 Specialize in detection and grounding Object detection, GUI grounding, text localization, document analysis, and point localization
4 Improve performance in dense scenes Previous training data combined with dense-object datasets

To align the MoonViT visual characteristics with the Qwen2.5 language decoder, only the MLP projector is trained during Stage 1. Stage 2 involves training the full model on a wide range of multimodal tasks. Stage 3 presents detection and grounding supervision, while Stage 4 leverages dense-scene datasets like MOT20Det and SKU110K to concentrate on tiny, overlapping, and visually comparable objects.[5]

Training Data

More than 12 million photos, 138 million natural language searches, and 785 million bounding boxes may be found in LocateAnything-Data. The dataset's emphasis on complex scenes, where a single image may include several labelled items, is reflected in the huge number of bounding boxes relative to images.[3][5]

General object detection, referring-expression comprehension, GUI grounding, text localization, document and scene-layout grounding, and point-based localization are all included in the dataset. Due to its diversity, the model may function in a range of visually complex contexts, including natural sights, papers, application interfaces, driving situations, and robotics.

LocateAnything employs online stream packing to merge the training samples into more effective sequences since they vary widely in length and complexity. MagiAttention prevents unrelated packed samples from attending to each other while controlling the combination of causal, block-causal, and bidirectional attention.[5]

Inference Modes

Three inference modes are offered by LocateAnything-3B:

Fast Mode

Speedily generates bounding-box coordinates by using pure parallel decoding. It is designed for scenarios when processing speed is of utmost importance.

Hybrid Mode

The default option. It strikes a compromise between speed and localisation quality by combining sequential generation across distinct boxes with concurrent prediction inside each bounding box.

Slow Mode

Conventional autoregressive decoding is used. Although it is slower than the other modes, it is compatible with conventional vision-language model production since the output is created token by token.[5]

Implementation

The project makes use of a Gradio interface for interactive testing and the nvidia/LocateAnything-3B model from Hugging Face.[9][10] Users choose an inference mode, pick a localization task, submit a picture, and respond to a natural language inquiry. After the model processes the picture and prompt, the produced coordinates appear on the output image as bounding boxes or points.

There are many task options available in the interface:

Object Detection

Several item types may be found in a picture using object detection.

Phrase Grounding

Finds a particular object that the user has described, such as "the person wearing a red shirt."

OCR

Locates and recognizes text that is visible in an image.

GUI Grounding

Locates interface components in screenshots, including buttons, icons, and menus.

Pointing

When identifying a single place is sufficient and a full bounding box is not required, pointing returns a single coordinate.

Demonstration

Sample photos will be used to showcase the Gradio program during our presentation. The ability of LocateAnything-3B to identify objects, text, interface elements, and other indicated locations will be demonstrated through various prompts, task choices, and inference modes.

The experiments below were run in a Jupyter notebook on the NJIT Wulver GPU cluster and move from ordinary scenes to more difficult, crowded environments so that both the model's strengths and its limitations can be observed. Every test follows the same procedure: load and resize the image, send a grounding phrase or list of categories, parse the model's normalised coordinates (0–1000), draw the predicted boxes, save the annotated result, and record false positives, missed items, and accurate detections.

Experiments

01

Street-Scene Object Detection

In an outdoor setting with items at various sizes and distances, this test assesses typical open-vocabulary detection.

Query
person car bicycle
Challenge

Large foreground items should be easier to find than smaller, partially visible, or near-image-boundary objects.

Results & Observations

The model produced 11 bounding boxes across all three requested categories. People, automobiles, and bicycles were among the output, demonstrating that the model could react to many category labels in a single request.

With a reported rate of around 0.42 boxes per second, the recorded generation time was roughly 26.20 seconds. Some predictions sat close to the margins of the picture, so the annotated output should be visually examined for boxes that could be missing or abnormally big.

Because the specified categories differ visually from one another, this test offers a helpful baseline.

02

Office and Desk Object Detection

This test assesses the model in an interior workplace scenario with common objects that could overlap or appear at varying sizes.

Query
computer mouse cup keyboard plant
Challenge

Little items like a mouse or cup might be harder to find than a large computer, and several plants may appear at varying sizes and locations.

Results & Observations

The office-scene test generated 7 bounding boxes. One computer, one mouse, one cup, one keyboard, and several plant forecasts were among the output.

The run reported around 3.28 boxes per second and finished in about 2.13 seconds. Despite the appearance of a CUDA memory-allocation warning, the annotation was stored as desk_detection_result.jpg and the inference still finished.

This image generated a cleaner output and fewer predictions than the street scene. The model performed best on large, clearly visible objects, while smaller or partially obscured things required deeper visual assessment.

03

Dense Grocery-Shelf Detection

This test assesses detection in a crowded shop environment with several little, aesthetically similar objects.

Query
pasta box
Challenge

Repeated rectangular packaging, similar colours, tiny labels, overlapping goods, and closely spaced items fill the shelf, making it harder to distinguish authentic pasta from visually identical soup, broth, and other food packaging. The image is shrunk to consume less GPU memory and cropped to remove the bottom watermark.

Results & Observations

The parser showed 20 complete predictions from the produced text, although the model statistics indicated 21 boxes. One last prediction may not have been properly reflected in the parsed result since the output exceeded the max_new_tokens=128 limit.

Particularly on the left side of the shelf, the model detected a number of packaged and cup-shaped pasta items. However, the crowded scene also produced classification mistakes:

  • A few boxed goods, such as soup or broth, were labelled as pasta boxes.
  • On the lower-right shelf, a number of real pasta items were overlooked.
  • The wide category query did not pick the displayed Whole Wheat Elbows box.
  • Similar packaging resulted in missed detections as well as false positives.

Although dense layouts and similar packing make exact category separation more challenging, this experiment shows that LocateAnything can recognize repeated items in a congested situation.

04

Broad Phrase Grounding

In this test, the objective is to locate a single object from a natural-language description instead of identifying every object in a category.

Prompt
a pasta box on the bottom shelf
Setup

To exclude irrelevant goods and lessen the quantity of visual data the model processes, the picture is cropped to the lower shelf.

Results & Observations

Instead of choosing the specified Whole Wheat Elbows pasta box, the model chose a neighbouring chilli product and returned one bounding box.

Although the shelf position was included in the description, there was insufficient information to set the target apart from other rectangular packages. This outcome shows that a good bounding box does not necessarily imply proper grounding of the intended item.

05

Refined Phrase Grounding

This test looks at whether grounding accuracy is improved by a more precise description and a tighter crop.

Refined Prompt
the blue and yellow pasta box labeled Whole Wheat Elbows
Improvements

The updated prompt adds the colours of the packaging, the kind of product, visible label writing, and a smaller visual area with fewer distracting items. The aim is less unclear due to the additional language and visual indications.

Results & Observations

The improved test returned one bounding box surrounding the specified Whole Wheat Elbows product region.

The more specific language and narrower crop yielded a more focused outcome than the general request. This implies that visual grounding can be enhanced when the trigger incorporates unique colours, language, and object characteristics, and when irrelevant elements of the scene are eliminated.

06

Clothing-Store Scene & Query Refinement

This test assesses the model in a different packed store setting with apparel and accessories, and looks at whether detection quality can be improved by altering the item categories.

Initial Query

Prompt
clothing glasses jewelry
Note

The code passes this as one unified description instead of producing distinct category-by-category results for clothes, glasses, and jewellery, so regions match the whole phrase.

Initial Results

Throughout the store, the model identified a number of apparel products and racks. The majority of forecasts concentrated on large, eye-catching clothing. However, because jewellery and spectacles were tiny, hard to identify, and not readily apparent at the enlarged image quality, no boxes containing those items were returned.

Several of the clothes boxes did not designate specific outfits; instead, they spanned whole rack portions or overlapped.

Refined Query

Prompt
dress shirt jacket clothing rack handbag
Change

Objects that were easier to see in the picture were added to the query, replacing the small, ambiguous accessories with larger, visually distinct categories.

Refined Results & Observation

Results from the enhanced query were more precise and insightful. The model recognised various areas with hanging garments, a shirt, a jacket, purses, and clothes racks. Smaller spaces for clothing and handbags were found on the left and center of the picture, while the enormous garment rack on the right was plainly visible.

Particularly in the congested left half of the store, several bounding boxes still comprised groupings of products or overlapped.

Since the chosen categories were larger, more visually distinct, and plainly visible in the image, the enhanced query performed better. The original test revealed that small accessories and wide categories can be challenging to identify, while the improved test indicated that using image-appropriate and specific item labels can increase recognition quality.

Overall, Test 6 demonstrates that LocateAnything-3B is sensitive to both prompt selection and scene complexity. More precise, comprehensive, and practical bounding-box predictions were obtained by fine-tuning the required categories.

GPU-Memory Considerations

The Wulver session provided approximately 9.75 GB of GPU memory. Dense scenes and repeated inference calls placed significant pressure on this allocation.

During experimentation, a broader grocery query caused a CUDA out-of-memory error after the earlier dense prediction had already consumed most of the available memory. The final workflow reduced memory use by:

  • Loading the model only once
  • Resizing large images
  • Cropping images to the relevant region
  • Using focused categories or phrases
  • Limiting max_new_tokens
  • Restarting the kernel when GPU memory remained occupied

The out-of-memory event was a hardware-resource limitation and was not treated as a completed model result.

Main Findings

  1. Clear categories performed well in everyday scenes. The street and office photographs yielded reasonable multi-object detections.

  2. Dense situations contributed to category confusion. Similar supermarket containers led to false positives and missing pasta goods.

  3. Prompt specificity mattered. The particular color-and-label prompt gave a more focused result, but the general pasta-box phrase picked the incorrect object.

  4. Image cropping was helpful. Removing irrelevant areas decreased GPU memory use and ambiguity.

  5. Improved detection was achieved by using categories that are readily apparent. In the context of clothes stores, predictions were more accurate when conspicuous items like shirts, coats, clothing racks, and purses were substituted for tiny or ambiguous accessories.

Related Work

Vision-language models grounded in open vocabulary have advanced fast, from dual-encoder cross-attention models to unified sequence-to-sequence models. We provide a comparison between LocateAnything-3B and relevant architectures below.

Grounding DINO
Dual image-text encoders combined with cross-attention feature maps to align text tokens and image regions. Despite being very good at phrase grounding, coordinate generation requires computing cross-attention matrices, resulting in inference latency issues, especially in dense images.
Florence-2
Unified sequence-to-sequence vision model covering grounding, OCR, and segmentation through text prompts. Nonetheless, Florence-2 needs sequential token generation for spatial coordinates, creating latency issues when predicting multiple objects.
Rex-Omni
Omni-modal visual perception system designed specifically for fine-grained object localization and GUI parsing. Although it performs very well on complex UI arrangements, it has a very high computational cost and uses more VRAM.
Qwen2.5-VL
Uses a powerful multimodal LLM backbone for complex spatial reasoning and zero-shot detection. Nonetheless, autoregressive coordinate prediction (token by token) leads to geometrical coherence and slow decoding speed issues.
LocateAnything-3B ★
Combines a MoonViT-SO-400M image encoder with a Qwen2.5-3B-Instruct architecture, where the autoregressive process is substituted with Parallel Box Decoding (PBD). Using one pass for simultaneous prediction of coordinate patches (Fast Mode / MTP), it reaches up to 2.5× faster inference compared to autoregressive methods while keeping the hybrid mode option (Slow Mode / NTP).

Limitations & Future Work

Although our qualitative assessment confirmed the advantages of speed and localization by LocateAnything-3B, certain limitations were observed in the course of implementing the solution:

  • Dataset Coverage and Quantitative Assessment: Our assessment is currently limited to qualitative images instead of using common benchmark datasets (mAP scores on COCO and LVIS). In addition, there may be minor coordinate offsets with non-zero sampling temperatures due to generation variation.
  • Limitation of Comparative Assessment: Owing to time limitations in project implementation, we could not evaluate our photographic dataset through competing open-vocabulary models such as Grounding DINO, SAM + CLIP, and YOLO-World.
  • Ambiguities in Visual Perception & Coarse Grouping: A high level of repetition in package design, small accessories, and occlusions often lead to false positives, or even to grouping several closely placed items together in a single coarse bounding box.
  • Hardware Limitations & Time Frame: Performing inference with the 10 GB GPU VRAM limitation would not allow batching full-resolution multi-images. Moreover, the model is unable to track objects across time frames since it uses only individual static frames.

Future Work Agenda

To address these limitations, future project iterations will prioritize:

  • Cross-Model Empirical Benchmarking: Conducting rigorous head-to-head empirical performance testing against all competing models (Grounding DINO, YOLO-World, Florence-2) using our bespoke image testing suite, providing quantitative comparison of mAP, latency and VRAM overheads.
  • Automated Dynamic Tiling (SAHI): Incorporating Slicing Aided Hyper Inference (SAHI) to dynamically tile high-resolution images into multi-ROI tiles to fix small-object misses while keeping VRAM usage under control.
  • Video Tracking Integration: Pairing LocateAnything-3B with video trackers (such as ByteTrack or DeepSORT) for real-time video-stream multi-object tracking capability.
  • LLM-based Prompt Pre-processing: Creating an automated prompt pre-processing system that expands simple user inputs into complex spatially detailed prompts before running inference.

Conclusion

In this paper, we investigated LocateAnything-3B, an open-vocabulary visual-linguistic grounding model created to mitigate the latency issues caused by the autoregressive coordinate generation approach used in traditional models. The combination of the MoonViT vision encoder and the Qwen2.5-3B language backbone together with the proposed Parallel Box Decoding (PBD) approach enables the model to generate coordinate blocks in one inference step — providing a 2.5× speedup compared to autoregressive approaches such as Qwen2.5-VL and Grounding DINO without sacrificing geometric accuracy.

Our quantitative and qualitative experiments across various task types show promising results in terms of the speed–accuracy trade-off in general visual grounding, dense perception, GUI element detection, and document parsing. Still, there are certain limitations in terms of visual ambiguity in repetitive and cluttered scenes due to coarse box aggregation and small-object skipping.

To move toward real-time application of LocateAnything-3B, future work would concentrate on incorporating automated dynamic tiling (SAHI) to enable VRAM-bounded small-object detection, in addition to combining the system with temporal tracking systems (ByteTrack). LocateAnything-3B thus moves the state of the art forward in efficient and generalist visual perception systems.

Broader Impact & Ethical Considerations

LocateAnything-3B and other open-vocabulary visual grounding models have practical uses in physical AI systems, GUI automation, and accessibility aids. Yet there are certain ethical issues to be taken into account in deployment of the technology:

  • Privacy in Public Domains: Since evaluation of such a model will require testing on images captured in the street or at offices, privacy issues related to personal data such as faces and license plates need to be properly considered by using automated anonymization pipelines.
  • Safety of Autonomous Systems: Since false positives and coarse bounding-box aggregation may be encountered in complex scenes, the model is not suitable for use as a standalone autonomous detector.
